# Notifications from the computer

Tentacle lets a paired computer show a message to the phone owner and, when
requested, wait until the owner acknowledges or dismisses it. Normal messages
are the default. Urgent alerts are available only after the owner explicitly
allows them in the app.

## Phone API

Every request uses the normal bearer token. To create a notification:

```text
POST /v1/notify
Authorization: Bearer <phone token>
Content-Type: application/json

{"title":"Optional title","text":"The task finished","level":"normal","id":"client-generated-id"}
```

`text` is required and has 1–1000 characters. `title` is optional and has at
most 100 characters; the app uses **Tentacle** when it is absent. `level` is
`normal` or `urgent` and defaults to `normal`. `id` is optional, contains 1–64
characters from `[A-Za-z0-9_-]`, and is generated by the phone when absent.
Control characters are rejected except newline. Invalid input returns 400.

The successful response describes what the phone actually did:

```json
{"id":"client-generated-id","level":"normal","downgraded":false,"shown":true}
```

An urgent request made while **Allow urgent alerts** is off is delivered as a
normal notification with `"downgraded":true` and
`"reason":"urgent_not_allowed"`. If Android does not allow full-screen
intents, the alert remains urgent and high priority, with
`"downgraded":false` and `"reason":"full_screen_not_allowed"`. If the app's
notification permission or selected channel is blocked, `shown` is false and
`reason` identifies the problem so the computer can report it.

Client-chosen ids make retries safe. Reusing an id with the same title, text
and requested level returns its original result without displaying or counting
another notification. Reusing it with different content returns 409. The phone
keeps the latest 50 records in memory only.

Normal notifications are limited to 10 in a sliding one-minute window. Urgent
notifications are limited to 3 in a sliding ten-minute window. An urgent
request that is downgraded counts against the normal limit. A new request over
its applicable limit returns 429 `rate_limited`.

To read or wait for the outcome:

```text
GET /v1/notify/<id>?wait=<0..60>
Authorization: Bearer <phone token>
```

The response is one of:

```json
{"id":"client-generated-id","level":"normal","state":"shown"}
{"id":"client-generated-id","level":"normal","state":"acknowledged","acknowledged_ms":1763371721000}
{"id":"client-generated-id","level":"normal","state":"dismissed"}
{"id":"client-generated-id","level":"normal","state":"expired"}
```

`level` is the level actually shown. With `wait > 0`, the request blocks until
the state leaves `shown` or the timeout elapses. Notification, verification-code
and app-request long-polls share a two-worker cap so file requests retain
capacity. An unknown or evicted id returns 404. A delivery with `shown: false`
starts in `expired`. After a successful display, `expired` is an explicit
terminal state for a notification that is no longer active without a tap or
swipe; records do not expire on a fixed timer. In particular, ending an urgent
alert's two-minute sound and vibration cap leaves its state as `shown`.

## Phone behavior and settings

Normal messages use the **Messages from your computer** channel at default
importance. Android's channel sound and vibration settings apply. The
notification uses an expanded text view; tapping opens Tentacle and records
`acknowledged`, while swiping records `dismissed`.

**Allow urgent alerts** is off by default. Turning it on explains that an
urgent alert can ring and vibrate continuously on the lock screen until
acknowledged, for up to two minutes. Allowed urgent alerts use the **Urgent
alerts from your computer** high-importance channel with alarm audio attributes
and repeated vibration. Android's channel setting controls whether it may
bypass Do Not Disturb.

An urgent alert can open a full-screen lock-screen activity with one large
**Acknowledge** button. The notification also has an **Acknowledge** action.
Either action stops sound and vibration and records acknowledgement. Sound and
vibration also stop if the activity is destroyed or after two minutes; the
notification remains available and its state remains `shown`. On Android 14
and newer, Tentacle shows a settings shortcut when full-screen intent access is
missing. It still posts the urgent heads-up notification with alarm sound.

The settings screen reports missing notification permission, blocked channels
and missing full-screen access with a shortcut to the relevant system setting.
**Test normal** and **Test urgent** exercise the same delivery path; the urgent
test is disabled until urgent alerts are allowed.

## Computer command

```text
tentacle notify TEXT [--title T] [--urgent] [--wait-ack [SECONDS]] [--json]
```

The computer generates an id before posting, so its one retry after a transport
failure is idempotent. Plain output reports `delivered`, explains an urgent
downgrade or unavailable full-screen alert, or prints `not shown: <reason>`.
`--wait-ack` waits up to 300 seconds when no value is supplied, using long-poll
chunks of at most 55 seconds; an explicit value changes the overall timeout.
Acknowledgement or dismissal exits 0. A notification that was not shown, rate
limiting or no response before the deadline exits 1. Usage and pairing errors
exit 2. Without `--wait-ack`, `--json` prints the delivery object as one JSON
value. With both options, stdout uses JSON Lines: the delivery object first,
then the terminal acknowledgement or dismissal object when one is received.

Agents should notify after a long task finishes, when they need a decision, or
when they are blocked and the owner is unlikely to be watching the computer.
Use normal notifications by default, keep the text short and do not spam.
Request `--urgent` only when the owner explicitly asked to be woken or alerted
for that particular event. Use `--wait-ack` only when work cannot safely
continue until the owner has seen the message.
