# Alerts from the computer

Tentacle provides three levels: **Normal alert**, **Ring alert**, and **Forced
alert** (普通提醒 / 响铃提醒 / 强制提醒). Normal is the default. The phone owner
must enable ring and forced separately in **Settings → Alerts**. Enabling a
level does not authorize agents to use it for unrelated events.

## Phone API

All endpoints require the usual bearer token. These are additive API v1
extensions; file access and transcript contracts are unchanged.

```text
POST /v1/notify
Content-Type: application/json

{"title":"Optional title","text":"The task finished","level":"normal","id":"client-generated-id"}
```

Bodies are at most 16 KiB. `text` has 1–1000 Unicode characters; `title` is
optional, at most 100 characters, defaulting to Tentacle. Control characters
except newline are rejected. `id` is optional, 1–64 characters from
`[A-Za-z0-9_-]`, generated by the phone if absent. Invalid input returns 400.
`level` accepts `normal` (default), `urgent`, `ring`, or `forced`. `ring` is an
alias normalized to `urgent` before idempotency comparison and in responses.
The public name for the compatibility API value `urgent` is **Ring alert**.

```json
{"id":"client-generated-id","level":"forced","downgraded":false,"shown":true}
```

The result describes the delivered level. `downgraded` is exactly whether that
level differs from the normalized requested level. Allowed downgrades are:

| Request | Owner setting | Delivered | Reason |
|---|---|---|---|
| `urgent` / `ring` | Ring off | `normal` | `urgent_not_allowed` |
| `forced` | Forced off, ring on | `urgent` | `forced_not_allowed` |
| `forced` | Forced off, ring off | `normal` | `forced_not_allowed` |

Forced does not require ring permission. Missing full-screen access keeps ring
or forced delivery and reports `full_screen_not_allowed`. Missing notification
permission or a blocked selected channel returns `shown:false` with a reason.
Those delivery failures take precedence over downgrade reasons.

The latest 50 records stay in process memory. Reusing an id with identical
title, text and normalized requested level returns the original result without
another display or rate-limit charge; different content returns 409. Normal
has a sliding 10-per-minute limit. Ring and forced share a sliding
3-per-10-minutes limit. The delivered level determines the window. Excess new
requests return 429 `rate_limited`.

```text
GET /v1/notify/<id>?wait=<0..60>
```

Returns `{"id","level","state","acknowledged_ms"?}`. State is `shown`,
`acknowledged`, `dismissed`, `expired`, or the forced-only `timeout`. A failed
delivery starts `expired`; successful display starts `shown`. With `wait>0`,
the call waits until state leaves `shown` or the deadline. Unknown/evicted ids
return 404. Notification, code and request polls share two waiting workers.
Terminal states never change. An alert that cannot start safely or loses its
notification before startup becomes `expired`. Ring's two-minute sound cap leaves `shown`.
Forced's sound cap records `timeout`. Only a correct question answer can
acknowledge forced alerts; it acknowledges the answered alert and every other
forced alert still `shown`. An answer after timeout closes its notification
without changing `timeout`. Turning forced off deliberately records
`dismissed` for forced alerts still ringing. Swiping never dismisses forced.

## Phone behavior and settings

**Normal alert — always on** uses the system notification sound/vibration
settings. Tap opens the notification inbox and acknowledges; swipe dismisses.

The main screen's **Notifications** button opens the same inbox. It keeps the
latest 200 successfully displayed computer notifications in app-private storage
across restarts. Each entry shows the full title and text, receipt time and
alert level. All unviewed notifications and the tapped notification form the
expanded **Current notifications** batch; previously viewed notifications are
under **History**, collapsed by default. New arrivals join the current batch
while this screen is visible, and rotating the phone preserves the batch and
history disclosure. A later visit shows the next unviewed batch. Merely reading
this screen does not acknowledge other notifications or silence alarms. Forced
notification taps continue to open the question screen. Alerts received before
this feature was installed are unavailable. This local history is independent
of the unchanged process-memory API status/idempotency records.

**Allow ring alerts** defaults off and retains the `urgent_allowed` preference
key. **Ring style** (`ring_style`) is **Vibrate and sound** (`both`, default),
**Vibrate only** (`vibrate`), or **Sound only** (`sound`). Ring keeps the
existing two-minute cap, lock-screen activity and **Acknowledge** action.
Acknowledgement, swipe, disabling ring, or activity destruction stops its
alarm; the cap/activity destruction leaves the notification available.

**Allow forced alerts** (`forced_allowed`) defaults off. Its confirmation warns
that the alarm volume changes and the alarm continues until a question is
answered or the sound cap is reached. **Alarm volume**
(`forced_volume_percent`) is 10–100%, default 100% (**Maximum**).
The target stream index is `max(minIndex, ceil(maxIndex * percent / 100))`,
using `getStreamMinVolume` on API 28+ and 1 earlier. **Stop sound after**
(`forced_cap_minutes`) offers 5, 10, 15, 20 or 30 minutes, default 10.
The settings show the question source/count actually used for the current app
language, level-specific test buttons, and
shortcuts for missing notification, channel and full-screen permissions.

Forced audio uses looping `MediaPlayer` with `USAGE_ALARM`, trying the default
alarm, notification, then ringtone URI. If none can be prepared, a generated,
looping two-tone `AudioTrack` pattern supplies alarm audio. Repeating vibration
and a partial wake lock last for the cap. Every two seconds, the app reapplies
the target if the alarm volume was lowered. The question activity consumes
volume keys and Back. Home, screen-off, recreation and activity destruction do
not stop the alarm. Full-screen intent access opens that activity on the lock
screen; notification taps always open it. Forced notifications are ongoing,
have no Acknowledge action or snooze, and a delete intent quietly reposts them.

Before the first forced volume change the app synchronously persists the
stream (`alarm`) and exact saved index with `SharedPreferences.commit()`.
Concurrent forced alerts share that one saved value. Correct answer, final
sound cap, or switching forced off stops the sound/vibration and restores the
saved index before clearing the persisted value. If other forced alerts are
still ringing, restoration waits for the last one. At a cap, a quiet question
notification remains and state becomes `timeout`. `TentacleApplication.onCreate`
restores and clears any saved value left by a killed/crashed process, before
initializing notification delivery. A failed restoration retains the saved
value so a later recovery can retry.

### Why the alarm stream

Forced alerts use `AudioManager.STREAM_ALARM` with `USAGE_ALARM`. AOSP's default
`MODE_RINGER_STREAMS_AFFECTED` excludes alarm, so silent/vibrate ringer modes
normally do not mute it. Priority DND allows alarms by default
(`ZenModeConfig.DEFAULT_ALLOW_ALARMS`), unlike ring/notification audio. Some
vendors, including Xiaomi MIUI/HyperOS, expose a separate Alarm slider while
silent mode silences calls and notifications. Device settings and vendor audio
policy can override these defaults.

`USAGE_ALARM` selects alarm/sonification policy rather than media policy, which
is appropriate for waking the owner. Speaker/headphone/Bluetooth routing is
ultimately device-dependent; it is not a universal speaker-output guarantee.
Changing alarm volume normally needs no notification-policy access because it
does not toggle DND. Android requires that access if an adjustment would toggle
DND. **Total silence** DND also mutes alarms and can ignore volume changes;
the app reads the volume back and logs `forced volume not applied` if the
target did not take effect. Forced alerts cannot override Android policy.

Primary references: [AOSP AudioService](https://android.googlesource.com/platform/frameworks/base/+/master/services/core/java/com/android/server/audio/AudioService.java),
[AOSP ZenModeConfig defaults](https://android.googlesource.com/platform/frameworks/base/+/bafc1f5a4e19842582a55ec1aae02e00d0b12f64/core/java/android/service/notification/ZenModeConfig.java),
[AudioAttributes](https://developer.android.com/reference/android/media/AudioAttributes#USAGE_ALARM),
and [AudioManager.setStreamVolume](https://developer.android.com/reference/android/media/AudioManager#setStreamVolume(int,%20int,%20int)).

## Questions

The pure-JVM bundled bank contains at least 45 English and 45 Simplified
Chinese questions across math, geography, physics, chemistry, biology, history
and language. Questions have short, stable, unambiguous answers. Chinese app
language selects Chinese questions; other languages use English. Selection is
random without repeating the previous question when alternatives exist.
After two wrong answers on one question the UI changes it and explains why.

Answer normalization applies NFKC (including full-width forms), trims,
collapses internal whitespace, lowercases with `Locale.ROOT`, and drops
trailing `.`, `。`, `!`, `！`. Any normalized accepted answer matches.

```text
PUT /v1/notify/questions
Content-Type: application/json

{"questions":[{"lang":"en","q":"12 × 3 = ?","answers":["36","thirty-six"],"domain":"math"}]}
```

This token-protected endpoint is routed before `/v1/notify/<id>`. A body is at
most 64 KiB and contains 0–300 questions. `lang` is `en` or `zh`, `q` is
1–200 characters, `answers` has 1–10 strings of 1–60 characters each, and
optional `domain` is at most 30 characters. No field accepts control
characters; answers must remain nonempty after normalization. Unknown root/item fields and explicit `domain:null` are invalid. Any invalid
item returns 400 without changing storage. Oversized bodies return 413.
The validated bank is atomically written to the app-private
`filesDir/notify-questions.json`. An empty list restores the bundled bank.
For each language, computer questions are used if any exist; otherwise the
bundled questions for that language remain available.

Both PUT and `GET /v1/notify/questions` return a summary (never the answers):

```json
{"source":"computer","count":60,"counts":{"en":30,"zh":30},"updated_ms":1763371721000}
```

`source` is `computer` or `bundled`; `updated_ms` is optional for bundled data.
Counts describe the selected source, including both languages.

## Computer commands

```text
tentacle notify TEXT [--title T] [--level normal|ring|forced] [--urgent]
                    [--wait-ack [SECONDS]] [--json]
tentacle notify questions [show]
tentacle notify questions push FILE
tentacle notify questions clear
tentacle notify questions generate [--count N] [--out FILE] [--no-push]
```

`--urgent` remains an alias for `--level ring`; ring is sent as `urgent` for
old phones. A `forced` request rejected with 400 is retried once with the same
id as `urgent`; plain output says “phone app does not support forced alerts;
sent as a ring alert”, and JSON adds `"fallback":"urgent"`. The actual
response still reports any further owner-setting downgrade. Transport retry
also preserves the id.

`--wait-ack` defaults to 300 seconds and polls in chunks of at most 55 seconds.
Acknowledged or dismissed exits 0. `timeout` prints “forced alert stopped after
its time limit without an answer” and exits 1. Not shown, rate limiting or no
response exits 1; usage/configuration/pairing errors exit 2. `--json` prints
one delivery object, or JSON Lines with delivery then terminal state when
waiting. A forced acknowledgement proves a correct answer, not just a tap.

`questions` as the first positional dispatches to the question commands; a
notification whose entire text is the single word `questions` is unsupported.
`push` reads the object above or a bare list; `show` prints the summary and
`clear` pushes an empty list. Old phones return GET 404 / PUT 405; the command
reports “the phone app is too old for custom questions”.

`generate` requires `[notify] question_command`, a shell-style split command
string with no default. Configure a generic AI CLI that reads a prompt from
stdin and writes text to stdout; Tentacle invokes argv without a shell. Missing
configuration exits 2 with a hint. `[notify] question_timeout_s` defaults to
300. The fixed prompt asks for `--count` English and the same number of Chinese
questions (default 30 each), spread across the seven domains above, in the
exact schema, with multiple accepted forms and no time-sensitive facts.
Surrounding prose or Markdown fences are accepted around the JSON object.
Invalid items are dropped, duplicates removed, and fewer than ten valid
questions per language fails. The same phone field/body limits apply.
Generated output is data and is never executed. `--out` writes the validated
JSON; normally it is pushed and its phone summary printed. `--no-push` keeps
the result local.

## Compatibility and agent use

Old computers keep using `normal` and `urgent` unchanged. Old phones reject
`forced` and `ring` with 400; the new computer sends ring as `urgent`, falls
back from forced, and diagnoses missing question endpoints.

Agents use **Normal alert** by default. Use **Ring alert** only when the owner
asked to be alerted for that event, and **Forced alert** only when the owner
explicitly asked to be woken or forced for that event. A phone opt-in is not an
event-specific request. Use `--wait-ack` only when continuation requires the
owner's response; no response or timeout must never be treated as approval.
